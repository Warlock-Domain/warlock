# src/worker — Cloudflare Workers + Durable Objects

Applies together with the root `CLAUDE.md`. Types separately: `npx tsc --noEmit -p src/worker`.

- **Every message goes through `parseClientMessage` first** (`webSocketMessage` in `room-do.ts`); an invalid one answers `{ t: 'error', code: 'bad_msg' }`. The `playerId` comes from the socket attachment, never from the message. The client only knows public ids (`byPublic()` translates).
- One socket is one person: `hello` with another id is refused; a second tab of the same player drops the first (`other_tab`).
- **Load and lifecycle:** `node scripts/room-load-soak.mjs` runs only on local Wrangler; it measures concurrent rooms/clients, snapshot rate, command latency, reconnection, ghost, joining near cleanup and five-minute retention. Record the load before fixing latency/capacity targets. The local Worker does not expose the Durable Object's CPU/memory.
- **Ghost connection:** a socket's close may never arrive. The `alarm()` (every 5 min) closes with `dead` whoever has not answered the 'ping' for `DEAD_MS` (90 s; counted from `hello`, stored in `at` in the attachment) and releases the player as in a disconnection. Proof: `node scripts/ghost-socket.mjs <url>` (~6 min).
- Two liveness signals, with different roles: the client's `'ping'` (every 10 s) is answered by the runtime (`setWebSocketAutoResponse`) and, on the room side, only counts toward `DEAD_MS`; the `{ t: 'alive' }` (every 5 s, during the match) arrives as a message and does **not** count as a human command for `IDLE_MS` (a match with everyone idle ends in 3 min; the sandbox never ends for inactivity, it only stops the loop when nobody is connected).
- Game commands (`move`, `stop`, `cast`, `item`) only enter the queue with the match in `playing`; the `seq` goes to `acks` (the client reconciles the prediction).
- Business rules belong to `match.ts`: the worker calls the function and, if it returns `true`, does `await this.changed()`.
- **Per-player limit** for a message that writes the room: follow the pattern of `look` (per-player map + window in ms, 100 ms) and of taunt (`TAUNT_COOLDOWN_MS`).
- **Write only in `changed()` → `persist()`**, never in the 16 ms loop. `persist` writes the match without the `World`. In `changed()`: notifies clients, turns the loop on or off, arms the alarm, only then writes disk and lobby (a lobby failure does not freeze the room). A call that can fail goes in `try/catch` with a comment.
- **Room cleanup:** after an `await` on a lobby RPC, recheck the revision and the connections before deleting the disk. A `hello` can come in during the RPC; republish the room if the revision changed. Every minute the lobby inspects at most 8 empty entries at a time, removing only rooms without persisted state; a failed inspection keeps the entry. `node scripts/room-cleanup.mjs` reproduces races without waiting 5 min; `node scripts/lobby-reconcile.mjs` covers batch reconciliation, a failed RPC and concurrent update.
- **Telemetry:** completed non-sandbox, non-Campaign rounds call `lobby().record(roundRecord(...))`; Sandbox and Campaign do not record round telemetry. Optional browser resource samples go through the `resources` client message and `lobby().recordResources(...)`; Sandbox and Campaign are excluded. Both aggregates live in the lobby Durable Object. See [`docs/resource-telemetry.md`](../../docs/resource-telemetry.md) for storage keys, endpoints, limits, and measurement caveats.
- Resource messages, like `alive`, do not reset `IDLE_MS`; background reporting must not keep an inactive room open.
- **Routes** (`index.ts`): a chain of `if` on `url.pathname`. Telemetry reads use `GET /api/telemetry` and `GET /api/telemetry/resources` (JSON with `cache-control: no-store`); details live in [`docs/resource-telemetry.md`](../../docs/resource-telemetry.md). Other paths return 404.
- **Forum** (issue #366): `/forum` is a second Vite page (`forum.html`) that the assets binding serves, so `run_worker_first` stays untouched. Every `/api/forum/*` route lives in `forum-api.ts`; the `Forum` Durable Object (`forum-do.ts`, SQLite, migration v2, one instance named `forum`) holds the sound lab tables (`sound_candidates`, `sound_votes`, `sound_comments`, created on construction; voting never closes); topics arrive later. **Sound lab** routes live in `forum-sounds-api.ts` under `/api/forum/sons` (members only through `forumMember`, which applies the session and Origin rules; kept out of `forum-api.ts` so its Vitest graph has no R2 types); files sit in the `SOUNDS` R2 bucket (`warlock-sons`, `pr-env.yml` swaps it for `warlock-sons-pr`) at `pack/<path>.mp3` (+ `pack/index.json`, uploaded by `scripts/assets/sound-pack.mjs`) and `up/<random>.<ext>`; the server checks upload size and type only, the 5 s limit is checked in the browser. The AI picks of `src/shared/sound-picks.ts` are options of their effect without a row (`isPick`). Sign-in: GitHub OAuth app owned by the org (`read:org`), random `state` in a 10-minute cookie, membership by `GET /user/memberships/orgs/Warlock-Domain` = `active`; the session is the signed user itself (HMAC, `forum-auth.ts`, pure and tested), `__Host-` cookies (`HttpOnly; Secure; SameSite=Lax; Path=/`, so no other subdomain such as a PR environment can plant one), 7-day sessions, the GitHub token is never kept. POSTs also check `Origin`. Secrets: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `FORUM_SESSION_KEY` (`wrangler secret put` on the live Worker, `.dev.vars` locally, plus `FORUM_ORIGIN` because `wrangler dev` rewrites the request host to the live domain); without them `/api/forum/me` answers `login: 'off'`. PR environments get `FORUM_TESTER=1` and a per-deploy `FORUM_SESSION_KEY` (uploaded as a secret, never a plain var) from `pr-env.yml`; tester mode never overrides real GitHub keys, so only "sign in as tester" exists there (Fernando, 25/10). HTTP bodies are validated by their own parsers in `src/shared/forum.ts`, not by `parseClientMessage`. `wrangler.jsonc` stays comment-free: `pr-env.yml` parses it with `JSON.parse`.
- Each PR publishes a separate Worker (`warlock-pr-<n>`, `.github/workflows/pr-env.yml`): `wrangler.jsonc` does not change per environment; the pipeline swaps only name and route.
